# The Nameless Chart

## What broke
`Chart.yaml` had an `appVersion` but no `version`. Before rendering a single template, Helm validates
the chart metadata, and three fields are mandatory: `apiVersion`, `name` and `version`. A chart
without a version cannot be identified, packaged, stored in a repository or tracked in release
history — so Helm refuses it outright and nothing reaches the cluster.

## Why Helm behaves this way
A chart has two versions that are easy to confuse:
- `version` — the version of the **chart** (templates + defaults). Must be SemVer 2 (`0.1.0`, `1.4.2`).
  It is what `helm package` puts in the file name (`webapp-0.1.0.tgz`), what repositories index, and
  what dependency constraints like `~0.1.0` match against.
- `appVersion` — free-form, informational: the version of the **application** the chart deploys
  (`1.27`). It shows up in `helm list` and is often used as the default image tag.
Bumping the image without bumping the chart version (or vice versa) is legal, but they move independently.

## The fix
Add `version: 0.1.0`, run `helm lint`, install. Lint checks all required metadata in one go.

## In real life
Charts hand-written by application teams, copied out of a monorepo or generated by scripts often miss
metadata. CI that runs `helm lint` before `helm package` catches it in seconds instead of during a
deploy window. Many teams also enforce "every chart change bumps `version`" so repositories never serve
two different charts under the same version.

## Commands worth remembering
- `helm lint ./chart` — validate metadata, templates and values without a cluster
- `helm show chart ./chart` — print the parsed Chart.yaml
- `helm create mychart` — scaffold a correct chart to compare against

## Common mistakes
- Treating `appVersion` as the chart version — it is informational only.
- Applying `helm template | kubectl apply` to "get it running" — you lose release history, upgrades
  and rollbacks because Helm doesn't know the resources exist.
- Using a non-SemVer version like `1.0` or `v1` — some Helm commands accept it, repositories and
  dependency ranges will not behave.

## Helm 3 vs Helm 4
Both refuse a chart without `name` or `version`. Helm 4 is more lenient about a missing `apiVersion`
than Helm 3 was (it installs such a chart) — `helm lint` still flags it, which is one more reason to
lint in CI.
